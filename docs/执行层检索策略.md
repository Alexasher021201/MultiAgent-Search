# 执行层检索策略：实现、配置与验证

本次实现把“禁止联网、RAG 必经、搜索次数限制”等规则落实到服务端执行路径。
模型负责提出调用请求和整理答案，策略层决定调用是否被放行，固定前置流程保证必需步骤发生。

## 1. 实际执行路径

```text
POST /api/task（query、retrieval_mode、allow_web）
  → 服务端解析不可变 RunPolicy
  → 创建本轮 RunContext，生成独立 run_id
  → RAG_ONLY / RAG_FIRST：代码直接完成助手发现和知识库查询
  → 把检索结果作为资料交给主智能体
  → 模型提出 task / internet_search 等调用
  → ToolPolicyMiddleware 校验并原子预占额度
  → 实际工具入口再次校验并认领同一个凭证
  → 调用 SDK，记录结果与执行事件
  → 整个图正常结束后报告完成，最后关闭本轮上下文
```

固定 RAG 流程位于规划模型之前。模型即使不调用工具、直接返回答案，也不能跳过该步骤。
RAG 失败、没有可用助手或名称存在歧义时会得到明确状态，不会伪造查询成功。

## 2. 每个模块负责什么

| 文件 | 职责 |
| --- | --- |
| `agent/execution_policy.py` | 定义检索模式、不可变策略、AUTO 首版规则；显式禁止联网与服务端开关可以收紧权限 |
| `agent/run_context.py` | 保存每轮状态、真实助手注册表、原始问题、共享预算；用锁原子检查和预占；通过 ContextVar 传递 |
| `agent/policy_middleware.py` | 同步/异步拦截模型及工具调用；拒绝时不执行 handler；向子助手附带本轮真实检索资料 |
| `agent/retrieval_workflow.py` | 执行固定 RAG 前置流程；使用配置名称或唯一候选，不让模型猜助手 |
| `tools/ragflow_tools.py` | RAG SDK 适配、HTTP 超时、结构化状态、引用提取、临时会话清理；更新执行事实 |
| `tools/tavily_tool.py` | 工具入口校验；独立统计 HTTP 尝试；只对超时、连接故障、限流做有限重试 |
| `agent/main_agent.py` | 给主智能体与四个业务助手安装中间件；建立/清理本轮上下文；运行前置流程和总超时 |
| `api/server.py` | 校验检索模式，传入用户限制，每次请求返回独立 run_id |
| `api/static/index.html` | 提供模式选择，显示策略、放行、拦截、检索结果和本轮统计事件 |
| `prompt/prompts.yml` | 保留业务提示词，增加只有服务端读取的 execution_policy 配置 |
| `tests/test_execution_policy.py` | 用 fake 模型和 fake SDK 验证真实框架与应用入口，不访问外部服务 |

策略中间件实例不保存用户计数。主智能体、子智能体、同步工具工作线程共享当前运行对象，切换助手不会重新获得额度。

## 3. 检索模式与优先级

| 模式 | 行为 |
| --- | --- |
| AUTO | 使用服务端的保守关键词规则解析成其他模式 |
| DIRECT | 禁止 RAG 和网络检索；其他已有业务工具仍按当前项目配置可用 |
| RAG_ONLY | 必经 RAG；不论无命中、失败或最新动态需求，都禁止网络搜索 |
| RAG_FIRST | 必经 RAG；仅在允许补充的结果状态和预算下放行网络搜索 |
| WEB_ONLY | 无 RAG 前置，允许受预算约束的网络搜索；禁止 RAG 查询 |

服务端 enable_web=false、请求 allow_web=false、“不要联网/只查知识库”等显式文字限制都会收紧权限。
“只查知识库”会覆盖 WEB_ONLY 请求。模型的工具参数不能修改模式、预算或检索完成状态。

AUTO 目前是可解释的关键词规则：三角洲/威龙资料走 RAG_FIRST，内部知识问题走 RAG_ONLY，
显式搜索/最新新闻等走 WEB_ONLY，其他问题保守地走 DIRECT；“你知道三角洲吗”之类基础聊天走 DIRECT。
它不是完整语义分类器，也没有跨轮领域识别。指代、复杂否定、混合任务请显式选择模式，后续可另建路由评测和分类器。

## 4. RAG 状态如何决定是否允许联网

| 状态 | 含义 | RAG_FIRST 中的网络补充 |
| --- | --- | --- |
| 尚未完成 | 包括只调用了助手列表 | 拒绝 |
| success | 有回答且有带正文的结构化引用 | 普通问题拒绝；显式最新动态需求可补充 |
| no_hit | 返回空引用列表或没有回答 | 允许，但仍检查联网开关与预算 |
| unverified | 有回答但没有可用结构化引用 | 允许补充，不把它冒充为有证据的成功 |
| no_assistant | 未找到相关助手 | 允许补充，并明确说明知识库未查询成功 |
| error | 服务失败、配置名称错误、名称歧义等 | 默认拒绝；只有服务端启用故障降级才允许 |

引用存在是首版的可解释证据门槛，不等于语义充分性或事实正确性的保证。
最新动态目前按用户文字需求做保守判断，未实现文档时间戳校验或独立语义评估器。

原始问题保存在执行上下文。查询其他问题不能解锁本轮联网；首版不开放模型自由改写并重新检索。
助手发现只执行一次，查询结束后重复检索会被拒绝。max_rag_calls 是安全上界，不表示自动重试两次。

## 5. 修改服务端配置

在 `prompt/prompts.yml` 的 execution_policy 下配置：

```yaml
execution_policy:
  enable_web: true
  max_web_calls: 2
  max_rag_calls: 2
  max_web_http_attempts: 4
  max_tool_calls: 20
  max_model_calls: 12
  max_denials: 3
  timeout_seconds: 180
  rag_connect_timeout_seconds: 5
  rag_request_timeout_seconds: 20
  rag_completion_timeout_seconds: 90
  rag_cleanup_timeout_seconds: 5
  allow_web_on_rag_error: false
  deltaforce_chat_name: ""
  default_rag_chat_name: ""
```

deltaforce_chat_name 要填写 RAGFlow 中真实聊天助手的名称，不是知识库名称。
为空时，游戏问题只在助手名或关联知识库名包含“三角洲/Delta Force”的唯一候选中选择。
普通 RAG 请求使用 default_rag_chat_name；为空时也要求候选唯一。
候选歧义会返回配置错误；同名助手或可能被截断的列表也不会被静默当作唯一结果。

这里的发现范围是当前 RAGFlow API Key 可见的助手；尚未实现应用用户级的知识库授权。
修改 YAML 后需要重启服务。

## 6. 预算、并发与异常

- 一次放行先预占额度，再执行 I/O。检查和预占在同一把短锁内；不会持锁等待网络。
- 工具失败也消耗已放行额度。相同搜索词按空白及大小写归一化去重，不因失败自动返还。
- 中间件的调用凭证只允许工具入口认领一次，因此不会双计数；直接调用工具仍需独立通过校验。
- 所有业务助手共享本轮额度。框架自动附加的 general-purpose 委派入口会被明确拒绝，避免未覆盖的助手绕过。
- 网络工具一次最多两次 HTTP 尝试，实际尝试还受 max_web_http_attempts 总上限约束。
- 无上下文、关闭后的运行、预算耗尽都拒绝新的调用；累计违规达到上限终止本轮。
- RAG 连接超时默认 5 秒，列表/会话管理读取超时 20 秒，非流式问答读取超时 90 秒，清理读取超时 5 秒；每次请求还会按本轮剩余时间收紧。Tavily 单次请求超时为 20 秒；整个运行默认 180 秒。
- 非流式问答要等待 RAG 检索、模型生成和引用处理完成，不能与助手列表共用较短读取超时。ReadTimeout 不意味着前端会话失效；每轮使用独立 run_id 和临时 RAGFlow 会话。
- 每个 RAG HTTP 阶段记录耗时；超时结果附带 RAG_TIMEOUT、phase、error_type 和 timeout_seconds，区分发现助手、创建会话、生成回答及清理阶段。
- asyncio 取消不能强杀已在工作线程中运行的阻塞 I/O。底层请求仍可能等待单次超时退出，但关闭后的运行不能提交新状态或开始新的受控调用。

## 7. 使用示例

前端选择“只查知识库”，输入“三角洲威龙擅长什么枪械”。日志应先出现必需检索，再出现模型规划。
无论资料是否充足，这种模式都不会发出 Tavily 请求。

API 请求体示例：

```json
{
  "query": "三角洲威龙擅长什么枪械",
  "retrieval_mode": "RAG_ONLY",
  "allow_web": false
}
```

前置检索结果只作为资料交给模型；task 委派时由中间件再次附带，避免主模型漏传。
RAG_ONLY 本轮查询失败时直接报告失败，不再调用主模型，因此不能用上一轮答案掩盖本轮失败。
RAG_FIRST 默认同样停止；仅在服务端允许故障降级时继续交给模型处理。普通成功结果的答案质量仍需效果评测。

## 8. 离线验证

在项目现有 WSL 虚拟环境中运行：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/frontend_sessions.test.cjs
```

回归覆盖真实工具节点、同步/异步调用、子助手委派、并发预算、重复请求、缺失上下文、
RAG 状态、HTTP 重试、违规终止、真实应用入口的 RAG 必经顺序、总超时和 API 参数传递。
新增 test_rag_timeouts.py 用本地模拟 RAG HTTP 服务、真实 SDK 和真实 SQLite checkpoint 验证同一会话连续两轮：
问答超时独立配置时两轮均成功；第二轮超时时明确失败，模型调用为零，不复用历史答案。
模型及 Tavily/RAGFlow 均使用测试替身，没有消费线上 API。

本次范围是单进程检索执行策略。运行预算和事件记录未持久化，不提供跨进程共享额度、
任务队列、业务幂等、用户鉴权、SQL 只读校验或文件沙箱；这些属于后续工程化阶段。
